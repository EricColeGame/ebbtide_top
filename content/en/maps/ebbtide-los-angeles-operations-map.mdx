## How to Read the Map Interface, Layer by Layer

Most people open a map, zoom to their site, and stop there. That's how misreadings happen. Work the interface in a fixed order instead: counters first, then the basemap, then the scale bar, then the pins.

The counters tell you what kind of map you're looking at. A project with a handful of observations is a scouting tool, not a coverage assessment. The basemap tells you what's physically there — parking, jetties, beach access points, harbor walls. The scale bar tells you whether two pins are neighbors or a kilometer apart, which changes how you interpret them.

Zoom level changes meaning more than it changes pixels. At citywide scale the LA coastline compresses into a single arc, and a pin that looks like it's on the sand may actually sit several blocks inland. Always confirm a pin's position at site scale before you build a plan around it.

| Zoom context | What becomes visible | Best use |
|---|---|---|
| Citywide (LA basin) | Coastline arc, major freeways, harbor complex | Choosing which sub-region to work |
| District | Piers, marinas, beach lots, breakwaters | Planning access and timing |
| Site | Tide lines, jetties, individual structures | Verifying a pin sits where you think |
| Pin-level | Overlapping and near-duplicate records | Cleaning up before analysis |

## Filters, Datasheets, and Data Quality

Filters turn a map into a query. The date filter is the one people underuse: coastal conditions shift seasonally, and a record from a winter swell tells you something different than one from a flat summer afternoon. The user filter is an audit tool — if a single contributor dominates the dataset, treat the pattern as community reports from one observer rather than a consensus.

The location filter is best used last. Search a named place only after you've seen the whole basin, otherwise you'll never notice that the neighboring cove is empty.

| Filter | What it does | Practical use | Watch out for |
|---|---|---|---|
| Date | Limits pins to a window | Seasonal comparisons | Very narrow windows can return zero results |
| User | Shows one contributor | Auditing a single observer's records | Small samples skew interpretation |
| Location | Restricts to a named place | Site-level checks | Hides nearby gaps |

Data quality on a small project is a hands-on job. A few checks cover most of it.

| Issue | Symptom on the map | Fix |
|---|---|---|
| Duplicate records | Two pins nearly touching | Read both records before logging a third |
| Pin drift | Point sits inland or offshore | Re-check at site scale against the basemap |
| Datasheet mismatch | Records that don't compare cleanly | Confirm template before submitting |
| Stale coverage | Pins clustered in one season | Note the date when citing the map |
| Empty space | No pins over a long stretch | Treat as "no effort recorded," not "nothing there" |

## Mistakes That Make an Operations Map Useless

The Ebbtide Los Angeles operations map is easy to misuse in ways that feel like progress. Watch for these:

- **Reading absence as evidence.** A blank stretch of shoreline usually means nobody logged it, not that nothing was there.
- **Ignoring the scale bar.** A 300 m / 1000 ft bar at district zoom compresses distance dramatically.
- **Trusting pin precision.** Consumer GPS and hand-placed points both carry error; confirm against the basemap.
- **Skipping the datasheet.** Records that don't match the template can't be compared later.
- **Screenshotting instead of linking.** Screenshots go stale in a week; the live map view doesn't.
- **Working the dense cluster.** Adding a fifth pin where four already exist is lower value than the first pin somewhere new.

Community reports are the lifeblood here. A project with two members grows one observation at a time, and the map improves the moment someone logs a site that was previously blank.

## FAQ

**Is the Ebbtide Los Angeles operations map free to view?**
Yes. The map view is public on the project page and doesn't require special software — just a browser. You can pan, zoom, and apply filters without downloading anything.

**How current is the Ebbtide Los Angeles operations map?**
It reflects the dataset at the moment you load it. On a small project, that means the map can look identical for weeks and then change suddenly after a single field session. Always check the date filter rather than assuming freshness.

**Can I contribute to the map without being a member?**
Logging typically requires joining the project so your records attach to a member account. Browsing is open, but contributing is a deliberate step — which is good, because it keeps records attributable.

**What if the map shows almost nothing near my LA site?**
That's the most useful result you can get. Treat the gap as an assignment: confirm access, check the datasheet, log carefully, and reload the map to verify the pin landed correctly. One well-placed record on a sparse map is worth more than ten in a crowded one.
